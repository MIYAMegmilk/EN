## 1. ページ構成

ルームに入ってからページ遷移すると WebSocket / VC が切断されるため、**ルーム関連（ロビー→ゲーム→結果）は `room.html` 1ページ内のフェーズ切替**で実装する。

| ページ | 内容 |
|---|---|
| `index.html`（ホーム） | 「いますぐ飲む」+ マッチング待機表示 / 部屋リスト（タイトル・サムネ・タグ・人数、タグ絞込）/ 合言葉・コード入力 / 部屋作成フォーム / ログイン状態表示 |
| `login.html` | アカウント登録 / ログイン |
| `profile.html` | あだ名・趣味タグの登録・編集（要ログイン） |
| `room.html` | 部屋の中すべて: 参加者一覧（あだ名+タグ）/ チャット / VC・カメラ操作 / ゲームリスト・選択・進行・結果 / ノック承認・キック（ホスト）/ bot 表示 |
| `studio.html` | 自作ゲームの作成・編集・共有コード（担当は後決め。ゲーム=全員の一部） |

## 4. 実装順序（ちいかわ視点のロードマップ)

1. **チャット**（§3.9。軽い・bot の前提・VC のフォールバック）
2. **VC 音声の疎通検証**（最大の技術リスク。VPS + coturn + HTTPS で4人通話を確認）
3. 入室モードの v0.5 対応（合言葉・オープン入室・承認制の選択）+ ランダムマッチ
4. 認証 + プロフィール API（みつおのページと接続）
5. VC 本実装 → カメラ
6. タグ・サムネのプリセット配信、公開ルーム一覧 API

みつお・ひろしは 1〜2 の間も `public/app.js`（開発用ページ＝プロトコルの参考実装）を見ながら並行で着手できる。

## 5. 部屋サムネイル（v0.5 追補）

- 部屋リストに表示するサムネは**運営が用意したプリセット画像から部屋作成時に選ぶ**（ユーザーのアップロードは受け付けない。不適切画像の混入を構造的に防ぐ）
- 画像は `public/assets/` に置き、サーバーは画像IDのみ扱う（タグと同じ方式）

## 6. テスト・品質

- サーバー: `deno task test`（現在117件）。機能追加のたびにユニット+結合を足す
- フロント: 簡易 JS アサーション + 主要ブラウザ目視（iOS Safari 必須）
- PR 前に `deno task check` / `deno task lint` / `deno task fmt` を通す
