# 作業ボード（board）設計書

チーム開発で「誰がこれから何を作るか」が見えず、**同じ機能を2人が別々に作ってしまう**事故を防ぐための小さなサービス。

各メンバーの Claude Code が着手前に「これから何をするか」を書き込み、全員が読める。あわせて、オープン中の PR がどのファイルを触っているかを突き合わせ、**マージ時に他人の PR を壊す事故**も警告する。

## 1. 背景（実際に起きた事故）

2026-08-26 に、1日で2件の衝突が起きた。

| 事故 | 中身 |
|---|---|
| PR #33 がマージ → **#36 が壊れた** | 開いていた PR が触る `corridor.js` / `corridor.html` を、別の PR が大きく書き換えた |
| PR #34 がマージ → **#35 が壊れた** | どちらも `auth.ts` の同じ `saveProfile` を別の理由で編集していた |

**どちらも「同時に同じファイルを編集していた」わけではない。** 数日前に書き終えた PR が、後から入ったマージによって壊れた。

したがって、防ぐべき事故は2種類ある。

1. **着手の重複** — 同じ機能を2人が作り始める → **表明**で防ぐ
2. **マージによる破壊** — オープン中の PR が触る場所を、別の作業が書き換える → **PR 索引**で防ぐ

この2つは情報源が違う。1 は「まだどこにも存在しない情報」なので専用の置き場所が要る。2 は GitHub に実在するデータなので API で取れる。**両方をボードに集約し、メンバーは1箇所だけ見ればよい形にする。**

## 2. スコープ

### 作るもの

- **表明（claim）** — 誰が・何を・どのあたりを・どのブランチで作業中か
- **PR 索引** — オープン PR の変更ファイルを定期取得し、表明と突き合わせて警告
- **タスク（task）** — Issue にするほどでもない粒度のメモ
- **PR 宛メッセージ** — 特定のメンバーへの伝言。**保存はせず GitHub の PR コメントとして投稿する**
- **画面** — 人間が読む用の1枚
- **CLI とフック** — Claude Code から使う口

### 作らないもの

- 認可の細分化（全員が全部見える・書ける。4人のチームに権限管理は過剰）
- 履歴の永久保存（表明は完了・期限切れで消えてよい）
- GitHub Issues の置き換え（タスクは補助であり、正式な課題は Issues を使う）

### 一時的な仕組みであること

このプロジェクト期間限定の運用ツール。**要らなくなったら systemd unit を止めて KV を消すだけで撤去できる**構成にする。EN 本体には一切依存させない。

## 3. 全体構成

```
各メンバーの Claude Code
  ├ SessionStart フック  → 表明一覧を取得して表示
  ├ PreToolUse フック    → 表明の有無と重なりを確認
  ├ SessionEnd フック    → 表明を「中断」に落とす
  └ tools/board/board.ts → CLI（claim / list / done / task / msg）
        │
        │  HTTPS + トークン
        ▼
  VPS: board サービス（Deno + KV / EN とは別 systemd unit・別ポート）
        │
        ├ Deno KV（表明・タスク・PR 索引のキャッシュ）
        └ GitHub API（オープン PR の変更ファイルを定期取得）
```

**EN 本体（`server/`）とは完全に独立させる。** 同じリポジトリに置くが、プロセスもポートも KV も別。EN が落ちてもボードは動くし、逆も同じ。

## 4. データモデル（Deno KV）

### claim（表明）

| フィールド | 内容 |
|---|---|
| `id` | ULID |
| `member` | サーバーがトークンから解決する。クライアントは名乗らない |
| `sessionId` | Claude Code のセッション識別子。1セッション1表明 |
| `title` | 何を作るか（例: 「VC ルームの画面共有」） |
| `paths` | 触る予定のファイル・ディレクトリ（任意・配列） |
| `branch` / `prNumber` | 任意 |
| `status` | `working` / `paused` / `done` |
| `startedAt` / `heartbeatAt` | 期限切れ判定に使う |
| `note` | 補足 |

**`paths` を任意で持たせるのは、重なりの自動検出に効かせるため。** 無くても人間が読めば分かるが、あればフックが機械的に警告できる。

### task

`id` / `title` / `body` / `assignee`（任意） / `status`（`open` / `doing` / `done`） / `createdAt`

### prIndex（キャッシュ）

`prNumber` / `title` / `author` / `headRef` / `files[]` / `fetchedAt`

GitHub API から定期取得したものを保持する。**API のレート制限を避けるため、リクエストのたびに GitHub を叩かない。**

## 5. 期限切れとハートビート

**この種の仕組みが最も壊れるのは「セッションが落ちて表明が残り続ける」パターン。** 必ず対策する。

- `heartbeatAt` を CLI 呼び出しのたびに更新
- **`TTL = 8時間`** を過ぎた `working` は、一覧では「古い表明」として区別して表示する
- `SessionEnd` フックで `paused` に落とす
- **サーバー側で自動削除はしない。** 消えると「誰が何をやっていたか」が追えなくなるため、あくまで表示上の区別に留める

## 6. API

すべてトークン必須。`Authorization: Bearer <token>`。

| メソッド | パス | 用途 |
|---|---|---|
| GET | `/api/claims` | 一覧 |
| POST | `/api/claims` | 表明 |
| PATCH | `/api/claims/:id` | 更新（heartbeat / status） |
| GET | `/api/claims/check?paths=a,b` | **指定パスに重なる表明と、オープン PR を返す** |
| GET / POST | `/api/tasks` | タスク |
| PATCH | `/api/tasks/:id` | タスク更新 |
| POST | `/api/messages` | PR コメントとして投稿（保存しない） |
| GET | `/api/prs` | PR 索引（キャッシュ） |
| GET | `/` | 画面（HTML） |

`/api/claims/check` がフックの中核。**「このファイルを触ろうとしている」に対して、重なる表明とオープン PR を返す。**

## 7. 認証と秘密情報の保護（最重要）

**公開インターネット上に置く。** ここを誤ると、チームのトークンや GitHub トークンが漏れる。

### 7-1. メンバーごとの個別トークン

共有トークン1つではなく、**メンバーごとに別のトークンを発行する。**

- **認証と識別が同時に済む。** クライアントは自分が誰かを名乗る必要がなく、詐称もできない
- git の `user.name` による識別は採用しない（`git config` を書き換えれば誰にでもなれるため）
- 表示名（ちいかわ / ひろし / みつお）はサーバー側で持つ。メンバー側の設定は `.env` にトークン1行だけ

### 7-2. トークンは KV にハッシュで保存する

**平文で保存しない。** パスワードと同じ扱いにする。

- 発行時に乱数からトークンを生成し、**その場で1回だけ表示**する
- KV には **SHA-256 のハッシュだけ**を保存する
- 照合はハッシュ同士の比較。**タイミング攻撃を避けるため定数時間比較を使う**
- 万一 KV の中身が漏れても、トークンそのものは復元できない
- 紛失したら再発行（回復はできない）

### 7-3. リポジトリに入れないもの

| 対象 | 置き場所 |
|---|---|
| メンバーのトークン | 各自の `tools/board/.env`（`.gitignore` で除外済み） |
| GitHub API トークン | **VPS の `.env` のみ。クライアントには一切渡さない** |
| トークン→メンバーの対応表 | **VPS の KV のみ。リポジトリには置かない** |

`tools/board/.env.example` には**空の値とコメントだけ**を置く。EN 本体の `.env.example` と同じ流儀。

`PROJECT/.gitignore` の `.env` はスラッシュ無しのパターンなので、**`tools/board/.env` も自動的に除外される**（確認済み）。

### 7-4. ログに残さない

- **トークンを一切ログに出さない。** 認証失敗時も値を記録しない
- 記録するのは「どのメンバーが」「いつ」「どの API を」まで
- エラー応答にトークンを含めない

### 7-5. GitHub トークンをクライアントへ漏らさない

PR 索引は**サーバーが GitHub を叩いて結果だけを返す。** クライアントに GitHub トークンを持たせない。

**注意**: `tools/pr-review-bot/lib/github.ts` は**運用層（`c:\intern	ools`）にあり、この repo からは import できない**（別リポジトリで、運用層は push されない）。したがって GitHub クライアントは `tools/board/` 内に新規に書く。あちらは**参考実装として読むだけ**にする。

必要な機能は限定的（オープン PR の一覧と、各 PR の変更ファイル一覧の取得）なので、フル機能のクライアントは要らない。

### 7-6. 画面のシェル HTML は無認証で配る。ただし中に情報を持たせない

**守りたいことは変わらない。** 誰が何を作っているかはチームの内部情報なので、**データは1バイトも無認証で出さない。** 変えたのは「どこで認証するか」だけ。

| 配るもの | 認証 | 中身 |
|---|---|---|
| `GET /`（画面のシェル HTML） | **不要** | **情報ゼロ**。空の器（レイアウト・CSS・スクリプト）だけ |
| `/api/*`（表明・タスク・PR・あだ名） | **必須**（`Authorization: Bearer`） | 実データはすべてこちら |

§6 の「すべてトークン必須」は `/api/*` に対する記述として読むこと。**無認証なのは `GET /` の1本だけで、それ以外は未知のパスも含めて認証を通す**（`POST /` も認証必須）。

#### なぜシェルだけ無認証にしたか（ブラウザの制約）

**ブラウザはトップレベルのページ遷移に `Authorization` ヘッダーを付けられない。** アドレスバーに URL を入れる・リンクを踏む、のどちらでも付けようがない。

そのため画面まで認証必須にすると、こうなる。

1. 利用者がボードの URL を開く
2. ブラウザは `Authorization` の無いリクエストを送る
3. サーバーが 401 を返す
4. **トークンを入力する画面が出ない** → トークンを持っていても入力する場所が無い

つまり「画面も認証必須」は、**画面を誰も開けない**という結論にしかならなかった。

回避策（Basic 認証のダイアログ、URL クエリにトークンを載せる、Cookie を配る）はいずれも §7-4「トークンを記録に残さない」と噛み合わない。URL に載せればブラウザ履歴・プロキシログ・Referer に残り、Cookie は CSRF の面倒を新たに背負う。

そこで**画面を「情報を持たないシェル」に保つ**という条件付きで、シェルだけを無認証にした。配ってもデータが1件も含まれないので、漏れるものが無い。

#### 前提条件（崩したら無認証にできない）

- **`tools/board/public/index.html` にデータを埋め込まない。** サーバー側のテンプレート展開もしない。表明・タスク・PR・メンバーのあだ名・トークンは、**すべて認証付きの `/api/*` から画面が自分で取りに行く**
- **トークンは `sessionStorage` に保持する**（`localStorage` は使わない。共用 PC で残るため）。URL にも記録にも残さない（§7-4）
- 画面は起動時に `sessionStorage` を見て、無ければトークン入力欄を出す。`/api/*` が 401 / 403 を返したらトークンを捨てて入力欄に戻す
- シェルにも**セキュリティヘッダを付ける**。CSP は `default-src 'none'` / `connect-src 'self'`（同一オリジンの `/api/*` だけ）／インライン `<script>` はハッシュで1本だけ許可、加えて `frame-ancestors 'none'`（`<meta>` では効かないのでヘッダー側にしか置けない）。`cache-control: no-store` も維持する
- **この前提が崩れていないことをテストで見張る**（§11）。実際に表明・タスクを作ってから `GET /` を叩き、その中身がシェルの本文に出てこないことを確かめる

無認証で足してよいのは「情報を持たない静的な器」だけ。**`/api/*` は1本たりとも緩めない。**

### 7-7. 表明の本文に秘密を書かせない

`title` や `note` は自由文なので、うっかり認証情報を書き込む余地がある。

- 画面と CLI の双方に「**秘密情報を書かないこと**」を明示する
- サーバー側で、明らかにトークン形式の文字列（`ghp_` / `gho_` で始まる等）を検出したら**拒否する**

### 7-8. その他

- **HTTPS 必須**（Caddy 配下）。平文 HTTP では受けない
- 認証失敗にレート制限をかける（総当たり対策）。EN 本体の `RateLimiter` と同じ流儀
- CORS は許可しない（ブラウザからの利用は同一オリジンの画面のみ）
- リクエストボディのサイズ上限を設ける

## 8. Claude Code 側の組み込み

**モデルの記憶に頼らない。** CLAUDE.md に「着手前に表明すること」と書いても忘れるので、フックで機械的に挟む。

`tools/hooks/guard-git-push.ps1` という前例があるので、同じ形で作る。

| フック | 動き |
|---|---|
| `SessionStart` | 表明一覧を取得して表示。**作業を始める前に必ず目に入る** |
| `PreToolUse`（`Edit` / `Write`） | 下記の判定 |
| `SessionEnd` | 表明を `paused` に落とす |

### PreToolUse の判定（強制の強さ）

**セッションで最初の `Edit` / `Write` のときだけブロックする。**

1. このセッションの表明が無い → **ブロック**し、表明を促す
2. 表明済み → 対象パスを `/api/claims/check` に問い合わせ
   - 他人の表明と重なる → **警告のみ**（通す）
   - オープン PR が同じファイルを触っている → **警告のみ**（通す）

**なぜブロックを1回に限るか。** 編集のたびに止められると鬱陶しく、**フックごと無効化される**。そうなれば何も残らない。防ぎたい「着手の重複」は作業開始時に起きるので、**1セッション1回で目的を達する。**

**なぜ重なりはブロックしないか。** 2人で分担している正当なケースがある。機械が判断できないので、警告して人間に委ねる。

### 通信できないとき

**ボードが落ちていても作業は止めない。** 接続失敗時はフックを素通りさせ、警告だけ出す。運用ツールが本業を止めるのは本末転倒。

## 9. GitHub API 連携

- オープン PR の一覧と、各 PR の変更ファイルを取得して KV にキャッシュ
- 更新間隔は**5分**。認証済み 5000 req/hour の枠に対して十分余裕がある
- 取得失敗時は古いキャッシュを返し、`fetchedAt` を添えて「いつ時点か」を示す
- **PR 宛メッセージ**は `POST /api/messages` を受けて GitHub の PR コメントとして投稿する。ボードには保存しない（**GitHub の通知で相手に届くため**。ボードに置くと見に来ない人には届かない）

## 10. 運用

- **EN とは別の systemd unit**（`board.service`）・**別ポート**
- Caddy でパスまたはサブドメインを割り当て
- `deno run` に渡す権限は必要最小限（`--allow-net` / `--allow-read` / `--allow-env` / KV の書き込み先のみ）
- KV は EN とは**別ファイル**にする
- 撤去は `systemctl disable --now board` と KV ファイルの削除だけ

## 11. テスト観点

`Deno.test` で、正常系・異常系・境界値を用意する。

- 認証: 正しいトークン / 誤ったトークン / トークン無し / ハッシュ照合が定数時間か
- 表明: 作成・更新・1セッション1表明の制約・TTL 判定の境界
- 重なり検出: 完全一致 / ディレクトリ配下 / 重ならない / パス無しの表明
- 秘密検出: `ghp_` で始まる文字列を拒否するか
- PR 索引: 取得失敗時に古いキャッシュを返すか
- レート制限: 認証失敗の連打を止められるか
- **ログにトークンが出ていないこと**
